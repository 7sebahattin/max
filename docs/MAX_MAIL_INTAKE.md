# MAX Mail 0.1 — mailbox-scoped safe intake

Issue #25. Independent from current verified main `059315f42a858510d507c1a78c9b8ee3f129698c`, targeting pinned Dolibarr 24.0.1. PR #23 is read-only research and remains unmodified/red. No cherry-pick, fixture file import or shared-file edit. The independent laboratory recreates its two failure conditions through a fresh RFC3501 subset, not the original diagnostic fixture suite. Whole-product coexistence/release qualification remains a later owner gate.

## Native-first boundary

Reuse Dolibarr's bundled Webklex client and its **public** `requestAndResponse()` / `readResponse()` protocol API. The latter validates the final tagged OK/NO; the native collector's array FETCH helper did not. MAX issues UID SEARCH UNDELETED and single-UID FETCH, checks UID/size/literal completeness and UIDVALIDITY again before accepting bytes. No native collector status `1` is treated as proof. MIME decoding reuses the public in-memory `Message::make` factory with explicit option 0/empty flags, preventing implicit flag writes. No native library patch/subclass replacement, new transport dependency, native agenda/order/stock/invoice action or SMTP sender exists.

## Implemented model and interface

- Native session, native CSRF, five MAX view/poll/review/download/admin rights plus explicit per-mailbox view/poll/review/download grants to existing internal native users. Global native/module admins are privileged; normal module view does not grant mailbox access. Every HTML/API/download/mutation repeats the server check. External users denied.
- Installation is the database/prefix boundary; entity + configured account + UIDVALIDITY + UID is unique. Message-ID/hash are secondary hints only, never globally unique. Connection identity is immutable; credential rotation preserves ledger identity. Disable polling without deleting evidence.
- Account-scoped MariaDB named lock plus connection-ownership fencing serializes polls and scope/config changes. A database unique key additionally protects source identities/parts. Deterministic entity/account/entry/part/content private paths prevent duplicate committed files after replay. Other databases are **NOT CERTIFIED**; unsupported safe locking is BLOCKED.
- Pending → verified fetched, or failed → retry_due (bounded backoff), then review_required after three attempts. Failed states/events are persisted; manual retry does not reset the attempt ceiling. Tagged NO, including partial data followed by NO, commits no bytes. Incomplete/unverified/oversized fetch stops that source in manual review; there is no automatic retry/release of that blocked path.
- UIDVALIDITY reset retires old identities, retains evidence and records new identities requiring reconciliation. A complete bounded UNDELETED scan can retire missing/deleted UIDs. Reappearance of a retired identity never recreates it or downstream documents. No downstream integration exists in this MVP.
- Private original and attachment storage outside webroot (directory 0700/file 0600); generated names, digest/size checked downloads, forced attachment/octet-stream and nosniff/sandbox. Raw original/quarantine additionally requires review+download scope. Never render mail HTML or fetch remote images.
- 2 MiB raw message preflight, 100-UID full scan ceiling, 10 attachments and 512 KiB per attachment. No silent truncated scan/deletion inference. Unverified MIME/size/signature/name becomes review/quarantine. All PDFs are unknown business types and quarantined; malformed/encrypted PDF is never released or guessed as PO/LL/PC. Oversized attachment bytes have no separate download; original remains bounded/private.
- Read-only inbox metadata, message/UID history, explicit retry/review acknowledgement, account/scope management. Acknowledgement does not clear quarantine, certify a document or approve any business action. From/Reply-To remains untrusted source attribution, not authorization; originals preserve headers.

## Setup / operation

Install source under `htdocs/custom/maxmail` or use the source-only ZIP generated by CI; enable via native module administration. Prototype module ID 610150 / rights 61015001–61015005 use collision checks, not public registry reservation. Commercial distribution/license review remains required. Module code is GPL-3.0-or-later and retains Dolibarr attribution; upstream stays separately pinned and unchanged.

Polling defaults to disabled (`MAXMAIL_ENABLE_POLLING` absent/0). An explicitly authorized installation administrator enables it in native configuration; this pilot sets it only in the disposable test database. Real-provider TLS configuration is implemented with certificate validation but **NOT TESTED/CERTIFIED**. Plaintext is allowed only with `MAXMAIL_ALLOW_SYNTHETIC_IMAP=1`, exact internal `fakeimap:1143`, no published server port, in isolated tests. There is no automatic scheduler or background send path. Configure each logical mailbox once, grant both global role and account scope, then manually poll from its inbox. A changed host/login/folder needs a new account; rotate credentials on the existing account for authentication recovery. API is native-session/form-CSRF based, not an external public REST integration.
